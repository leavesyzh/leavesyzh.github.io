FineWeb技术分析：为高性能大型语言模型策划数据集

FineWeb：大规模提炼网页以获取优质文本数据 - a Hugging Face Space by Ki-Seki

FineWeb 是一个大规模高质量的网页文本数据集，用于预训练大型语言模型。它基于 Common Crawl（CC）网页快照构建，总规模约 15 万亿 词元（约占用 44TB 磁盘空间），比常见的开源预训练数据集更大。FineWeb 取材自 2013–2024 年的 96 个 CC 爬取快照，在同样规模下训练出的模型性能优于其他公开数据集。FineWeb 的作者在提博客中详细记录了整个数据集的构建流程，包括去重和过滤策略，并公开发布了数据集和处理代码，以高大语言模型训练的透明度。此外，还提供了一个子集 FineWeb‑Edu（1.3 万亿和 5.4 万亿词元两个版本），该子集采用自动化的教育价值分类器筛选出高教育内容，能显著提升知识型基准（如 MMLU、ARC）上的模型表现。两个数据集均采用宽松的 ODC‑By 1.0 开源许可发布，方便社区复用。

优质数据集

在大多数情况下，特别是在大型语言模型预训练的背景下，高质量并不是一个定义明确的术语，甚至不是一个可以通过直接的人类观察就能清晰感知的文档属性。

评价一个数据集是否优质的方法主要有以下几种：

  1. 在给定的被认为干净的语料库上训练模型，并使用该模型检查需要评价数据集的困惑度。但是这种方法给出的评价并不能决定数据集在下游任务的性能上的表现。
  2. 在数据集的代表性子集上训练小模型，并在一组评估任务上对其进行评估。使用小模型是因为训练成本和时间与模型大小正相关，采用小模型可以节省资源。这种方法需要选择一组多样化且具有代表性的数据集评估任务，并尽量避免过度拟合任何一个单独的基准测试，因为这可能会损害预训练后获得的 LLM 的通用性。
  3. 在每个数据集上训练一个模型，并让人类对模型的生成结果进行评分和比较。这种方法提供的评价最为可靠，但是成本非常昂贵，而且这种方法还要求经过指令微调阶段以获得对话能力，而预训练模型并非直接设计用于遵循指令，因此对提示细节更为敏感。

消融实验和评估设置

消融实验（Ablation Study）是机器学习和深度学习研究中常用的一种分析方法，用于评估模型或系统中某个组件、特征或设计决策的贡献。

为了比较给定处理步骤的影响，作者在数据集的两个版本上训练了两个模型，一个版本应用了额外的步骤（作者希望评估的步骤），另一个版本则去除了该步骤。除了数据之外，这两个模型在其他方面完全相同：参数数量相同、架构超参数相同，并且在每个版本的数据中随机采样相同数量的标记进行单轮训练 —— 因此唯一的区别在于训练数据。然后，作者在相同的任务集上评估每个模型，并比较平均得分。

消融模型使用 nanotron 进行训练，有 18.2 亿个参数（包括嵌入层），使用 Llama 架构，序列长度为 2048，全局批量大小约为 200 万个标记，并使用 GPT2 分词器。对于大多数消融实验，作者在约 280 亿个标记上进行训练（大致是该模型大小的 Chinchilla 最优训练大小）。为了确认每次过滤步骤后的相对性能提升，作者在 3500 亿个标记上进行了更长时间的训练。

作者使用 lighteval 对模型进行评估，通过选择能够在相对较小规模（“小”模型仅在“几十亿”个标记上训练）下提供良好信号的基准测试，精心挑选了一组用于消融实验的基准测试。作者使用以下标准从 lighteval 中所有可用的基准测试中选择这些基准测试：

  • 在相同数据集的不同采样上训练的运行结果之间的方差较小：作者希望在数据子集上的运行结果能够代表整个数据集，并且最终得分在可能的范围内，对精确数据点选择的敏感性低于对过滤器效果的敏感性。

  • 在训练过程中性能单调（或接近单调）增加： 理想情况下，随着所见标记数量的增加，高信号基准测试的性能不应下降（这表明在小尺度下结果不可靠）。

  • 在该任务上的性能至少比随机基线高出几个标准差：鉴于小消融模型和训练，通常在任何基准测试中都无法达到极高的分数，但作者希望确保获得的分数高于随机噪声。

经过考虑，作者选择了以下基准测试列表：

  • 常识问答（Common Sense QA）
  • 超级难题（Hella Swag）
  • 开放书籍问答（Open Book QA）
  • 物理常识问答（PIQA）
  • 社交常识问答（SIQA）
  • 温诺格兰德（Wino Grande）
  • 美国学术评估测试（ARC）
  • 大规模多任务语言理解（MMLU）

FineWeb 的构建方法

FineWeb 以 Common Crawl 网页快照为原始数据源。构建过程中，作者使用 Datatrove 开源处理库，在多台 CPU 节点上并行执行数据过滤和去重操作，大大加速了流水线处理速度。总体数据处理管道包括以下主要步骤：

1. 文本提取

Common Crawl 提供两种数据格式：

  • WARC（Web ARChive）：包含网页的完整 HTML 内容及元数据；
  • WET（WARC Encapsulated Text）：提供从 WARC 中自动提取的纯文本版本，许多数据集使用 WET 作为起点。

但 FineWeb 实验发现：WET 文件中存在大量无关样板内容（如导航栏、页脚等），对 LLM 预训练不利。因此作者采用 Trafilatura 库直接从 WARC 中提取正文内容。通过视觉检查和模型训练对比，Trafilatura 提取的文本质量明显更高，训练结果也更优。

2. 数据过滤

数据过滤是大规模文本整理流程中的核心步骤，目的是剔除对模型训练无益甚至有害的内容。它可以发生在多个粒度层面（如单词、句子、段落或整篇文档），确保保留下来的数据具备较高的语言质量与语义价值。在 FineWeb 的构建中，基础过滤阶段主要参考了 RefinedWeb 的方法，并结合多个公开工具和自定义策略，构建出高质量的大规模语料库。具体包括以下几项：

  1. URL 黑名单过滤

    • 利用黑名单机制对网页来源进行控制；
    • 剔除包含成人内容、非法信息或严重噪声网页的 URL；
    • 保证语料的整体伦理性与合法性。
  2. FastText 语言识别
    • 使用 Facebook 开源的 FastText 多语言分类器；
    • 对每段文本进行语言判断；
    • 仅保留英文得分 ≥ 0.65 的段落（置信度阈值）；
    • 实验表明该阈值在准确率与召回率之间取得了良好平衡。
  3. MassiveText 质量与重复过滤器
    • 引入 MassiveText 提供的过滤工具链（使用其默认参数）；
    • 包括语法异常检测、重复样式识别、垃圾内容判定等；
    • 去除包含：
      • 明显乱码
      • 嵌套错误或断裂的句段
      • 高度模板化或重复结构的页面段落

3. 数据去重

数据去重是为 LLM 预训练创建大型网页数据集时最重要的步骤之一。数据集去重方法旨在识别和去除数据集中的冗余/重复数据。

网络内容存在大量重复，包括但不限于：聚合网站、镜像站点；模板化页面（如电商、新闻页）；抓取器误操作（如多个 URL 指向同一网页）。这些重复的数据会导致模型性能下降，预训练记忆泛化能力减弱，训练迭代效率下降等。因此，去重不仅有助于提高模型质量，还可以等效提升训练效率（即用更少的 token 训练获得相同性能）。

FineWeb 采用类似 RefinedWeb 的 MinHash 模糊哈希方法对文本进行去重。具体步骤如下：

  1. 文本切片（Shingling）
    将文本拆分成连续的 5-gram（连续五个单词的序列），以捕捉文本的局部结构和上下文信息。

  2. 哈希编码（MinHash 签名计算）
    对每个文本的 5-gram 应用 112 个独立的哈希函数，计算出对应的哈希值集合，形成文本的 MinHash 签名。

  3. 桶划分（Banding）
    将 112 个哈希值分成 14 个桶（每桶包含 8 个哈希值）。如果两个文本在任一桶中的所有 8 个哈希值完全匹配，则认为它们是高度相似的。

  4. 重复判定
    根据上述桶匹配情况，判定文本对的相似度是否达到或超过 75%，并将此类文本标记为重复。

  5. 去重执行
    在文本集合中识别出重复文本后，删除重复内容，保留唯一且高质量的文本数据。

  6. 实验策略调整

    • 初期尝试对所有抓取数据进行全局去重（跨快照），去除约 90% 数据，但模型性能未见提升。

    • 后改为对每个快照单独去重，获得约 20 万亿词元的数据集，训练效果与 RefinedWeb 相当。

FineWeb 的原始数据来自多个时间点的网页抓取快照（Common Crawl 中按时间分批次的抓取数据），这些快照中存在大量重复或高度相似的网页内容，尤其跨快照之间会有大量内容重叠（如新闻转载、模板页面、镜像站点）。全局去重指的是将所有时间快照的数据合并，统一进行重复检测，也就是说，除了在单个快照内部去重，还跨不同时间快照比对文本。如果一个网页内容在多个快照中都出现，只有一份会被保留，其他重复副本全部删除。利用 MinHash 模糊哈希技术，对整个多年份抓取数据做统一去重，结果发现经过去重后，数据量减少了约 90%，仅保留了大约 10% 的内容；换句话说，绝大多数内容被判定为重复并被剔除。

原因分析：

数据集规模虽大幅缩减，但实际训练数据的多样性可能下降：
去重剔除的大量数据中，部分虽然格式相似但内容有价值的网页也被误删，导致训练语料的多样性和覆盖度下降；

过度去重导致长尾内容受损：
一些特定领域或小众主题网页因结构相似，容易被误判为重复而被删除，减少了模型学习的知识广度；

跨快照去重可能导致时序信息丢失：
不同时间抓取的网页在某些信息上会有细微差别，统一去重导致这类细微差异丢失，影响模型对时间动态内容的学习；

模型训练未必需要极端去重：
训练大型语言模型时，适当的重复能帮助模型更好地巩固语言结构和重要知识，去除过多重复可能反而减少模型“记忆”的机会；

计算资源和去重误差的影响：
在海量数据上做全局去重，可能存在一定误判，导致高质量内容丢失，从而影响最终效果。

4. 额外的质量过滤

FineWeb 基础过滤及独立 MinHash 去重已达到与 RefinedWeb 相当的性能,但在综合任务中，另一历史悠久的数据集 C4 在部分基准上表现更优,因此，FineWeb 团队探索借鉴并超越 C4 的额外过滤策略，以进一步提升模型性能。

C4 数据集简介

  • 发布于2019年，基于2019年第18期Common Crawl转储；
  • 采用非英文数据过滤、启发式规则（如删除包含黑名单词的文档）、行级与文档级去重；
  • 规模约1750亿GPT-2标记，虽规模较小但因严格过滤而质量较高；
  • 被广泛用于多个大型语言模型训练（如Llama1），特别在HellaSwag基准表现出色。

FineWeb 借鉴 C4 过滤尝试

  • 过滤规则包括：
    • 删除不以标点符号结尾的行；
    • 删除提及 JavaScript 和 Cookie 通知的行；
    • 删除包含 “lorem ipsum” 或 “{” 符号的文档；
    • 限制行长度；
  • 发现终端标点过滤效果最显著，但同时导致约 30% 的标记被去除，过滤过于激进；
  • 综合去除除终端标点以外所有过滤器，性能提升明显且只去除约 7% 标记；
  • 最终决定采用除终端标点过滤器外的全部 C4 过滤器。

新启发式过滤器开发流程

  1. 统计指标采集
    收集超过 50 种文档级和跨文档指标（如行数、平均行长、重复率等），来源涵盖高质量与低质量网页数据；
  2. 指标筛选
    选择在高低质量数据间 Wasserstein 距离大的指标作为过滤候选；
  3. 阈值设定与验证
    观察指标分布直方图，选取经验阈值，使低质量数据趋近高质量数据区间；
    通过小规模消融实验验证过滤器效果；
  4. 针对低质量数据比例较高的全局 MinHash 版本，重点比较了多项指标，发现明显差异。
